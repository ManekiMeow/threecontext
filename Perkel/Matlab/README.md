# MATLAB port of the Perkel analysis

MATLAB translations of the three Mathematica notebooks in `Perkel/`. The
notebooks and data files are unchanged; each notebook has one MATLAB script
here, and the functions the notebooks define (`parseWave`, `filterPhase`,
`genMajorSeq`, `gramsch`, `deltalambdacorr`) have their own `.m` files.

| Mathematica | MATLAB | What it does |
|---|---|---|
| `PerkelTheory.nb` | `PerkelTheory.m` | Orthogonal representation of the complement of the Perkel graph, state lists for the three levels, homodyne efficiency, AFG pulse tables `impulse.txt` / `pmpulse.txt` |
| `PerkelData.nb` | `PerkelData.m` | Phase screening, Hardy-type paradox, NCHV violation with bootstrapped errors, amplitude correction, figures |
| `PerkelPostProcessing.nb` | `PerkelPostProcessing.m` | Extracts (intensity, LO phase, convolution phase) from the raw scope traces and writes `data1a.mat`, `data2a.mat`, `data3a.mat` |

## Running

From this folder in MATLAB:

```matlab
PerkelData               % runs PerkelTheory first, then the data analysis
checkAgainstMathematica  % runs both without figures and compares with the notebook outputs
```

Set `makePlots = false` before running a script to skip the figures.
`PerkelData.m` reads the original `data*.mat` files from `Perkel/`
(override with `dataDir`). `PerkelTheory.m` writes its `impulse.txt` and
`pmpulse.txt` into this folder, not over the originals.

`PerkelPostProcessing.m` needs the raw oscilloscope traces (`D:\pcdata\...`
in the notebook), which are not in the repository: set `rawDir` to their
location. Its output goes to this folder (`outDir`), in the same layout as
the Mathematica export, so `PerkelData.m` can read it.

## Agreement with the notebooks

Checked with GNU Octave 8.4 (MATLAB was not available); `checkAgainstMathematica.m`
reproduces the check.

- `impulse.txt` and `pmpulse.txt` regenerated by `PerkelTheory.m` are identical
  to the originals (all 1516 rows, at the 5 significant digits exported).
- Every deterministic number printed in `PerkelData.nb` is reproduced to at
  least 12 significant digits: filtered-repetition counts, phase means and
  deviations, `hardyprob` (total 2.99024), penalty 0.650940, corrected value
  2.33930, correlation 0.995771, detector fit 7.767 + 306.594 x.
- The homodyne efficiencies `eff` agree to about 1e-9 (numerical integration).
- The bootstrapped errors differ slightly (`penaltyerr` 0.0394 vs 0.0401,
  violation 8.16 vs 8.06 standard deviations), because MATLAB's `rng(8023)`
  draws different samples from Mathematica's `SeedRandom[8023]`.

## Notes on the translation

- `genMajorSeq`: Mathematica's `Sort[x, Abs[#1] < Abs[#2] &]` puts entries of
  equal magnitude (such as `+a` and `-a`) in reverse order of appearance,
  and it treats magnitudes that differ only by rounding error as equal. The
  MATLAB version does the same; this is what makes `impulse.txt` match.
- Level-3 states: Mathematica's `errlist` has 1199 entries because its `Tally`
  kept two copies of the state `{0,0,0,0,0,0,-1/9}` (entries 3 and 28) that
  differed only in the last bits. MATLAB's rounding gives 1198 distinct
  states, so `PerkelTheory.m` re-inserts the copy at entry 28. Without this,
  every level-3 state after 27 would be matched to the wrong measurement in
  `data3a.mat`.
- Plot styling: Mathematica's `ColorData[24]`, `[51]`, `[55]`, `[75]` and
  `"SunsetColors"` palettes and the Minion Pro / MaTeX labels have no MATLAB
  equivalent, so similar colours and default fonts are used. Layout and
  plotted data follow the notebooks.
- The "Electronic pulse representation" figure needs `samplewave.txt`, which is
  not in the repository; set `sampleWaveFile` to draw it.
- The Perkel graph is taken from the Gram matrix (entries 1/3) rather than
  `GraphData["PerkelGraph"]`, and its independence/chromatic numbers are
  confirmed directly (triangle-free; the three blocks of 19 are a proper
  3-colouring; the graph has odd cycles).
